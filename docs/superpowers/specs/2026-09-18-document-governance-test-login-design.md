# 文档治理台测试身份模拟设计

## 目标

在尚未接入可信网关的本地和测试环境，为技术文档治理台提供浏览器端的角色模拟入口，使现有接口能够接收到与网关契约一致的身份信息。该能力不实现真实账号、密码或组织管理，也不改变生产环境的网关鉴权要求。

## 范围与开关

- 新增配置 `strong.document-governance.test-login.enabled`，默认 `false`。
- 本地和测试环境显式配置为 `true`；生产环境保持 `false`。
- 新增只读配置接口，用于前端判断是否显示模拟登录入口；该接口被身份拦截器排除，关闭时只返回 `enabled: false`。
- 其余文档治理 API 继续由现有 `DocumentIdentityInterceptor` 校验，生产环境仅接受可信网关注入的三个身份头。

## 前端行为

文档治理台顶部增加测试身份控制入口，仅在开关启用时显示：

- 可选择 `member` 或 `admin`。
- 可填写用户 ID 和团队 ID；首次打开提供无业务含义的默认测试值。
- 点击确认后，将身份保存到 `localStorage`，刷新当前页面的数据和权限展示。
- 已保存的模拟身份展示在顶部，并可再次切换或清除。

前端请求封装在测试开关启用且存在模拟身份时，自动注入：

```text
X-Strong-User-Id
X-Strong-Team-Id
X-Strong-Role
```

关闭测试开关时，前端不读取或发送模拟身份，身份仍完全由网关决定。

## SSE 处理

浏览器原生 `EventSource` 不支持自定义请求头。文档 AI 任务状态流改为 `fetch` 读取 `text/event-stream`，复用普通请求的身份头，并解析现有 `status` SSE 事件。身份不会出现在查询参数或 URL 中。

## 后端组件

- 为测试开关新增受配置绑定的属性对象，并在配置接口中仅公开 `enabled` 布尔值。
- `DocumentGovernanceWebConfig` 排除该配置接口，其余现有拦截范围不变。
- 不修改 `DocumentIdentityInterceptor` 的角色和必填头校验逻辑。

## 验收与测试

- 配置关闭时，配置接口返回 `enabled: false`；普通治理接口仍缺少身份头即失败。
- 配置开启时，前端选择 `member` 和 `admin` 后，普通请求均携带正确身份头，管理员专属术语库操作随角色切换显示或隐藏。
- AI 任务状态流在模拟身份下可连接并处理状态事件，且请求 URL 不包含身份值。
- 后端新增配置接口和拦截器排除路径的单元或 MVC 测试；前端通过静态检查或浏览器验证请求头与角色切换。

## 非目标

- 真实登录、账号密码、会话令牌、SSO 和权限管理。
- 改变正式网关的身份头清洗与注入责任。
- 在生产环境允许浏览器伪造文档治理身份。
